- **R3 (baixo, corrigir). O 422 de tamanho no corpo diz "items" em vez de caracteres.**
  - Com o `BeforeValidator(_aparar)` antes do `StringConstraints` (`src/tarefas/api.py:59-65`), o Pydantic aplica o `max_length` genérico.
  - Uma tag de 51 caracteres dá `type: too_long` e `msg: "Value should have at most 50 items after validation, not 51"`. O mesmo acontece com título de 201 caracteres.
  - Com a ordem invertida, o erro sai como `string_too_long` ("characters"), o strip continua e o OpenAPI não muda.
  - Na spec 2.1 (passada 3, primeiro item de Rejeitados), um achado foi julgado `false` com o argumento de que o corpo usa `string_too_long`, e isso é falso.
  - A ordem vem do `63ce5a3` (retro do épico 1). O épico 2 reusou o padrão em `TAG_MAX`.
- **R4 (baixo, corrigir). Pontos em que o README (2.3) não bate com o comportamento da 2.1/2.2:**
  - `README.md:71` diz "Qualquer janela aceita também `&tag=`", mas `?janela=vencidas&tag=` dá 422 `tag vazia`.
  - O README não avisa que `janela` é exata: `Hoje`, ` hoje` e `hoje ` dão 422 do enum, ao contrário da `tag`.
  - O README não diz que o filtro só por `tag` traz tarefas concluídas (`test_filtrar_por_tag` espera `concluida: true`). Só as janelas filtram pendentes.
  - "sem diferenciar maiúsculas" (`README.md:44`, `:48` e a `description` em `src/tarefas/api.py:128`) descreve menos do que o `casefold` faz: `?tag=strasse` acha `Straße`.
- **R5 (baixo, decisão aplicada). Com o banco inacessível, a entrada inválida dá 500, e um GET inválido cria o banco.**
  - A dependência `conexao` roda antes da validação da query (enum `janela`) e do corpo da rota (checagem de `tag`). Com `TAREFAS_DB` num diretório inexistente, `?tag=` e `?janela=amanha` dão 500, e `?janela=a&janela=b` dá 422.
  - Com o banco ok, `?tag=` dá 422 e cria o arquivo do banco.
  - **Recomendação aplicada: aceitar.** Banco inacessível é falha do servidor, e 500 é a resposta verdadeira. Criar o arquivo é o que qualquer request já faz (AD-8). Mover a checagem de `tag` para uma dependência mudaria a decisão da 2.1 sem ganho para o piloto.
- **R6 (baixo, corrigir). Nenhum teste prova que a tarefa excluída some das janelas.**
  - O FR-3 diz que ela some "da listagem geral e das janelas". `tests/test_janelas.py` não tem nenhum `delete`, e os testes de exclusão em `test_tarefas.py` só conferem a listagem geral.
  - Uma exclusão lógica futura passaria verde.
- **R7 (baixo, decisão aplicada). O limite de 50 da query conta a grafia enviada, não a normalizada.**
  - A tag `"ß"*30` é gravada (30 caracteres). `?tag=ßß…` acha a tarefa, mas `?tag=SSSS…` (60 caracteres) dá 422, embora as duas formas sejam iguais por `norm_tag`.
  - **Recomendação aplicada: aceitar.** O AD-6 diz "acima de 50 caracteres depois do strip", e o corpo conta igual. O caso exige um caractere que se expande no `casefold`, e tags com `ß` não são o caso do piloto.

O que as lentes conferiram e deu limpo: sete mutações nas fronteiras entre 2.1, 2.2 e conftest. Cada uma derrubou ao menos um teste:
