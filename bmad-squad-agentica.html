Abertura (~1 min). Apresente-se e diga o objetivo: sair daqui sabendo instalar o BMAD, montar a base de um projeto e operar o dia a dia com uma squad de agentes.

Combine o formato: perguntas no final, mas pode interromper se algo não ficar claro.

Tudo o que vou mostrar é da versão 6.10 — se vocês viram material antigo com .bmad-core ou Gems, muita coisa mudou.

O problema

Um assistente sozinho escreve código, mas não sustenta um projeto

Onde um chat genérico vai bem
  • Escrever funções isoladas
  • Corrigir erros de compilação
  • Refatorar trechos de código
  • Acelerar protótipos
Onde ele se perde
  • O contexto some entre sessões
  • Decisões de arquitetura mudam a cada prompt
  • Sem critério de aceite, sem estratégia de testes
  • Ninguém lembra por que algo foi decidido

O problema não é o modelo. É a falta de estrutura em volta dele.

Por quê02 / 29

(~1,5 min) Pergunte: quem aqui já usa IA para codar? E quem já sentiu que o projeto desandou depois de algumas semanas?

Lado esquerdo: o chat genérico é ótimo em tarefas isoladas. Lado direito: o problema aparece quando o projeto cresce — o contexto some, decisões mudam a cada prompt, ninguém lembra o porquê.

Feche com a frase de baixo: o problema não é o modelo, é a falta de estrutura em volta dele. Essa é a ponte para o próximo slide.

Conceito

Squad agêntica é um time de papéis, não um chatbot

01

Papéis

Cada agente tem uma responsabilidade e um menu próprio de workflows: analista, PM, arquiteto, UX, dev.

02

Artefatos

Brief, PRD, arquitetura e stories ficam em arquivos versionados. Cada documento vira o contexto da fase seguinte.

03

Gates

Você revisa e aprova antes de avançar. Checagens como o readiness check e o code review seguram a qualidade.

O BMAD-METHOD é uma implementação open source desse modelo. O humano continua decidindo; os agentes executam com contexto.

Por quê03 / 29

(~1,5 min) Defina squad agêntica com três palavras: papéis, artefatos e gates.

Papéis: cada agente tem um foco, como num time real. Artefatos: o que um agente produz vira o contexto do próximo — isso substitui a memória do chat. Gates: você aprova antes de avançar.

Reforce: o humano continua decidindo. O BMAD é uma implementação open source desse modelo, e é ela que vamos ver.

O readiness check pega a lacuna antes de virar código

› bmad-check-implementation-readiness ▸ Resultado: CONCERNS ▸ FR-04 não define o fuso dos prazos ▸ Story 2.3 sem critério de aceite para "próximos 7 dias" › Fuso do usuário via header X-Timezone. Atualize PRD e story. ▸ (chat novo, nova checagem) ▸ Resultado: PASS
O que aconteceu
CONCERNSPASS

A checagem cruzou PRD, arquitetura e stories e achou uma decisão que ninguém tinha tomado.

Você decidiu, o PRD foi atualizado com bmad-prd → Update, e a segunda rodada passou.

04 · Simulação25 / 29

(~1,5 min) Aqui o gate mostra valor: o readiness check voltou CONCERNS porque o fuso horário do filtro por prazo nunca foi decidido.

Quem decide é você. A decisão volta para o PRD (intenção Update) e para a story, e só então a checagem passa.

Frase para fixar: essa lacuna custou uma conversa. Descoberta em produção, custaria um bug de prazo errado para todos os usuários.
